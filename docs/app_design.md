# App 设计定稿 v2（单房间模型）

更新日期：2026-08-06 | 本文件为 App 线开发的完整规格

## 一、MVP 流程（单房间）

```
首次启动 onboarding（生辰八字→命卦，可跳过/可改，仅存本地+加密）
开始分析 → 选【场景】(住宅/办公室) + 【房间类型】(卧室/厨房/书房/客厅/办公室/卫生间…)
  → 指南针校准（指向北记录磁航向θ₀；磁北基准，罗盘惯例）
  → ARCore 环绕扫描单房间（方案A：平面检测+特征点云，不依赖Depth）
  → 3D视图：物体识别标注 + 房间类型确认（以用户为准）+ 北箭头微调
  → 报告：命卦吉凶 + 命中规则 + 整改方案（含整改后对照表）
```

## 二、数据模型

```
UserProfile { birthInfo(公历生日+时辰, 加密存储), mingua }
RoomRecord  { scenario, roomFunction, facing?(可选坐向), northRotation,
              modelRef, objects[] }
Object      { type, pos3D, bbox, facing?, sector(卦位), movability }
```

## 三、技术决策清单

| 主题 | 决策 |
|---|---|
| 平台 | Android 优先，端上为主，全离线隐私 |
| 3D建模 | 方案A：ARCore 平面检测+特征点云+VIO 位姿→户型多边形+点位；不依赖 Depth API；3DGS 二期 |
| 识别范围 | 住宅 11 类 + 办公新增（见 dependency_matrix v3）|
| 物体朝向 | 三级：位置锥角近似(±30°+距离)→墙邻先验(床/沙发/灶/门)→用户微调；朝向未知不判定 |
| 方向基准 | 磁北（罗盘惯例，无需磁偏角修正）；θ₀ 记录 + 3D 视图人工微调 |
| 命卦/坐向 | 命卦路为主（四吉凶方，只需生辰+北向）；坐向可选（启用宅卦游年吉凶位）|
| 场景 | 住宅/办公室；办公=宅法举隅·衙署/学宫/店铺直接映射，用坐向+元运（弃用生辰）|
| 房间类型 | 核心输入（规则范围限定器）；扫描前选+扫描后确认 |
| 宅级规则 | 五虚降级为房间级重判；屋后门/四象等 dormant |
| 规则库 | 74 条（active 58/dormant 15/hidden 1）；6 书语料 17.5万字 |
| 冲突处理 | 保留较早出处，后出 hidden 完全不呈现（docs/conflict_registry.md）|
| 引擎 | 事实层→派生事实(卦位/相对关系/墙邻/密度)→规则求值→按物体聚合 |
| 整改求解 | 双层目标：硬约束(消凶+全量重评估无回归) > 软目标(构造吉)；L1移动/L2遮挡/L3改造；可移动/固定(含灶)/可新增屏风；无解给次优+权衡；整改后对照表 |

## 四、整改求解器（Remediation Solver）

```
对每个凶规则命中 v：
  variants = actions[L1→L2→L3]
  for action in variants:
      sim = 复制事实; apply(action, sim)
      hits2 = evaluate(sim)                    # 全量重评估
      if v 已消除 and hits2 无新凶:              # 硬约束（优先消凶）
          候选.append((action, 吉命中数))        # 软目标（构造吉）
  取吉命中数最高的候选；无候选 → 次优方案+权衡说明
输出：分级整改方案 + 对照表(逐项✓) + 无新凶声明/权衡
```

可移动性分类：可移动(床/沙发/餐桌/衣柜/冰箱/盆栽)、固定(门/窗/厕/墙/**灶**→只走L2遮挡或L3改造)、可新增(屏风/隔断)。

## 五、报告结构

```
概览：场景/房间类型/命卦/宅卦(若填坐向)/北方
吉组：命中规则（附最早出处徽标）
凶组：命中规则 + 整改方案（优先消凶、无回归、构造吉）
每条 = title + 白话结论 + 化解/整改 + [原文依据]折叠 + 最早出处
```

## 六、范围锁定

- 语料：6 书（葬书/宅经/发微论/阳宅十书/宅法举隅/阳宅大全），不再新增典籍
- 规则：74 条，不再扩（暂缓《阳宅集成》《八宅明镜》《阳宅三要》/现代资料）
- 识别：住宅 11 类 + 办公 desk/front_desk/cashier 等
- 隐私：全离线；生辰仅存本地并加密；不上传任何数据
